## 通用说明

### 统一响应格式（普通 JSON）

```json
{
  "code": 200,
  "message": "描述信息",
  "data": { }
}
```

- `code`：业务状态码（200 表示成功）
- `message`：提示信息
- `data`：具体数据（可能为对象 / 数组 / `null`）

> `POST /auth/login` 与 `POST /auth/register` 除上述字段外，还额外返回 `access_token` 字段（供 Swagger 的 Authorize 使用）。

### SSE 流式响应

```
Content-Type: text/event-stream

data: {"type": "start"}

data: {"type": "thinking", "content": "用户询问递归，我先回忆其定义..."}

data: {"type": "thinking", "content": "递归是一种函数调用自身的技术..."}

data: {"type": "chunk", "content": "递归"}

data: {"type": "chunk", "content": "是一种"}

data: {"type": "done", "content": "递归是一种编程技巧...", "messageId": 6}
```

**事件类型明细**（来自 `app/services/sse_stream.py`）：

| type | 触发时机 | 字段 |
|------|---------|------|
| `start` | AI 开始流式输出前 | 无 |
| `thinking` | 模型"思考过程"逐段输出（仅在模型开启 thinking 且返回 `reasoning_content` 时出现） | `content` (str)：本次的思考增量文本 |
| `chunk` | AI 每次输出正式回答文本片段 | `content` (str)：本次的文本片段 |
| `done` | 流式结束 | `content` (str)：完整回答；`messageId` (int)：AI 消息 ID |

> **思考过程展示**：`thinking` 事件由后端 monkeypatch 了 `langchain_openai.chat_models.base._convert_delta_to_message_chunk`（见 `backend/app/ai/reasoning_patch.py`），把阿里云百炼返回的非标准字段 `delta.reasoning_content` 透传到 `AIMessageChunk`。前端默认**展开**展示思考内容，收到第一段正式回答（`chunk`）后**自动折叠**，标题栏可随时点击展开/收起。
>
> **持久化**：思考过程随 AI 消息一起保存到 `messages.thinking` 字段（后端启动时自动 `ALTER TABLE` 迁移补充该列）。重新进入对话或刷新后，历史 AI 消息会以**默认折叠**的思考区块展示完整思考内容，点击「思考过程」可展开查看。
>
> **滚动体验**：流式输出期间前端仅在用户停留在底部附近时才自动滚动（`scrollToBottomIfNear`，`frontend/js/utils.js`），用户上滑阅读时不会被新内容打断。

> `error` 事件当前由后端异常抛出（断流），前端 JS 也做了 `"error"` 类型兜底处理。

### 错误响应

| HTTP 状态码 | 含义 | 示例 detail |
|:----:|------|------|
| 400 | 请求参数业务冲突 | `知识库中有文档正在处理中，请等待处理完成后再发送消息` |
| 401 | 未认证 / Token 无效 / 账号密码错 | `token无效或已过期`、`账号不存在！`、`密码错误！` |
| 403 | 无权访问或越权操作 | `无权操作该对话`、`无权访问该知识库！`、`该文档不属于此知识库` |
| 404 | 资源不存在 | `对话不存在`、`知识库不存在`、`文档不存在` |
| 409 | 资源冲突 | `用户名或邮箱已被注册！` |
| 422 | 请求体验证失败 | FastAPI 自动生成（如字段类型错误） |
| 500 | 服务器内部错误 | `删除向量数据失败` |

## 一、认证模块

### 1. POST `/auth/login` — 登录

**请求格式**：`application/x-www-form-urlencoded`（前端使用 `URLSearchParams`）

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| username | string | 是 | 用户名 **或** 邮箱 |
| password | string | 是 | 密码 |

**成功响应 (200)**：

```json
{
  "code": 200,
  "message": "登录成功",
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": {
      "id": 1,
      "username": "李灏",
      "email": "lihao@example.com",
      "avatar": null
    }
  }
}
```

**错误**：

| 状态码 | detail |
|:----:|--------|
| 401 | `账号不存在！` |
| 401 | `密码错误！` |

---

### 2. POST `/auth/register` — 注册

**请求格式**：`application/x-www-form-urlencoded`（前端使用 `URLSearchParams`）

| 参数 | 类型 | 必填 | 约束 | 说明 |
|------|------|:----:|------|------|
| username | string | 是 | 2–20 字符 | 用户名 |
| password | string | 是 | 6–20 字符 | 密码 |
| email | string | 是 | 6–100 字符 | 邮箱 |

**成功响应 (200)**：与登录响应结构一致，`message` 为 `注册成功`。

**错误**：

| 状态码 | detail |
|:----:|--------|
| 409 | `用户名或邮箱已被注册！` |
| 422 | 密码长度不足等字段校验失败（由 FastAPI 返回） |

### 4. POST `/auth/logout` — 退出登录

## 三、消息模块

### 12. POST `/message/send` — 发送消息（SSE 流式回复）

**请求头**：`Authorization: Bearer <token>`，`Content-Type: application/json`

**请求体**（`UserMessage`）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| chat_id | int | 是 | 对话 ID |
| content | string | 否 | 文本内容（与图片 / 文件至少有一个） |
| images | array | 否 | 图片数组，每项 `{ url, name }` |
| files | array | 否 | 文件数组，每项 `{ fileId, name, size, url }` |
| kb_id | int \| null | 否 | 知识库 ID，非空时 AI 会先检索该知识库内容再回答 |

**请求示例**：

```json
{
  "chat_id": 1001,
  "content": "请帮我解释什么是递归",
  "images": null,
  "files": null,
  "kb_id": null
}
```

**成功响应 (200)**：`Content-Type: text/event-stream`

**SSE 事件序列**：

```
data: {"type": "start"}

data: {"type": "thinking", "content": "用户询问递归，我先回忆其定义..."}

data: {"type": "thinking", "content": "递归是函数调用自身的技术..."}

data: {"type": "chunk", "content": "递归"}

data: {"type": "chunk", "content": "是一种"}

data: {"type": "chunk", "content": "编程技巧，"}

data: {"type": "chunk", "content": "函数在执行过程中调用自身..."}

data: {"type": "done", "content": "递归是一种编程技巧...", "messageId": 6}
```

**后端处理流程简述**：
1. 校验对话归属权 → 若传 `kb_id`，进一步校验知识库归属权与处理中状态
2. 保存用户消息（含 `images` / `files` JSON 字段）
3. 组装多模态消息：图片转 base64、非图片文件转文本、可选的知识库 RAG 检索结果
4. 调用 LangGraph Agent 以 `stream_mode="messages"` 逐 token 流式生成；其中模型的"思考过程"（`reasoning_content`）通过 `thinking` 事件先行下发，`chunk` 事件承载正式回答
5. 结束后保存 AI 消息，发送 `done` 事件（含该消息 ID）

**错误**：

| 状态码 | detail |
|:----:|--------|
| 404 | `对话不存在` |
| 403 | `无权操作该对话` |
| 404 | `知识库不存在`（`kb_id` 无效时） |
| 403 | `无权访问该知识库！` |
| 400 | `知识库中有文档正在处理中，请等待处理完成后再发送消息` |

## 四、文件模块

### 13. POST `/files/upload` — 上传文件

**请求头**：`Authorization: Bearer <token>`

**请求格式**：`multipart/form-data`

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| file | file | 是 | 上传的文件（前端限制 ≤10MB） |

**成功响应 (200)**：

```json
{
  "code": 200,
  "message": "上传成功",
  "data": {
    "fileId": "3f2a9d8c4b7e1a0f.json",
    "fileName": "数据.json",
    "fileSize": 102400,
    "fileType": "application/json",
    "fileUrl": "http://127.0.0.1:8000/uploads/3f2a9d8c4b7e1a0f.json"
  }
}
```

> 服务端以 UUID 重命名文件保存在 `uploads/` 目录，并对外暴露 `fileUrl`。
> 前端在选择文件后立即调用此接口上传，拿到真实 URL，再随消息一起发送。

**错误**：400 — `File not found.没有上传文件`

## 七、认证流程

```
1. 用户登录 / 注册 → 后端生成 JWT Token
2. 前端将 data.token 保存到 localStorage（key: ai_chat_token）
3. 后续请求请求头携带 Authorization: Bearer <token>
4. 后端 get_current_user 依赖校验 Token：
   a. 检查 Token 是否在内存黑名单
   b. 解码 JWT（sub = 用户 ID），校验签名与过期时间
   c. 查询数据库确认用户存在
5. 校验通过 → 接口正常执行；失败 → 401，前端跳转登录页
```

## 八、前端调用说明

- **API 基础地址**：`frontend/js/config.js` 中的 `API_CONFIG.baseURL`（默认为 `http://127.0.0.1:8000`）
- **请求封装**：`frontend/js/api.js` 的 `request()` 自动附带 Token、统一处理 401 与 FastAPI 错误格式
- **文件上传**：`uploadFile()` 走 `multipart/form-data`
- **SSE 消费**：`chat.js` 的 `sendMessage()` 用 `fetch + ReadableStream` 读取流，识别 `start / chunk / done / error` 事件

- SSE 流式打字机效果、"思考中"指示器
- 对话列表搜索、重命名、删除、清空
- 知识库创建 / 删除、文档上传与状态轮询、聊天时选择知识库
- 文件历史弹窗（当前对话 / 所有对话）
